## Problem Statement

Two coupled issues:

1. **Light mode is broken app-wide.** `ThemeData.lightTheme` is defined correctly in `lib/core/theme/app_theme.dart:219`, but **219 occurrences across 21 files** bypass it by referencing dark-mode-only constants like `AppColors.inkSurface` (#141416), `AppColors.textPrimary` (#F9FAFB), and `AppColors.inkHairline` directly. On a `paper` (#FBFAF7) background these render as black-on-white surfaces with invisible white text.
2. **Profile screen is functional but cluttered and inconsistent.** Single 8-tile settings list with no grouping, redundant reminder rows, fixed dark backgrounds in modal sheets, no scroll-aware app bar, awkward 4-up stats row that clips on narrow phones.

These are coupled because most fixes to the profile screen only render correctly once the underlying token migration happens.

---

## Root Cause Analysis

### Why light mode breaks

`AppColors` is a **flat palette of fixed-hex constants**, not a theme-aware accessor. Components that write `AppColors.textSecondary` get the same `#9CA3AF` gray on both backgrounds — barely readable on `paper`. Components that write `AppColors.inkSurface` get the dark-mode card color regardless of the active brightness.

The fix is **not** to add `if (isDark) ... else ...` branches in every widget — that's the anti-pattern. The fix is to route every widget through `Theme.of(context).colorScheme.*` (or the equivalent `TextTheme` accessors). The `AppColors.*` constants then become the **palette source for `app_theme.dart` only**, not the call sites.

## Technical Solution

### Strategy: Two-layer theming

```
Layer 1 — PALETTE (existing AppColors)
   Single source of truth for hex values. Used ONLY by app_theme.dart.

Layer 2 — SEMANTIC TOKENS (ColorScheme + custom ThemeExtension)
   What widgets read from. Switches automatically with brightness.
```

Add a small `ThemeExtension<AppSemanticColors>` for tokens Material's `ColorScheme` doesn't cover (xpGold, streakOrange, glassOverlay, success/warning when distinct from `tertiary`/`secondary`):

```dart
@immutable
class AppSemanticColors extends ThemeExtension<AppSemanticColors> {
  final Color xpGold;
  final Color streakOrange;
  final Color success;
  final Color warning;
  final Color hairline;          // distinct from outlineVariant for 1px rules
  final Color sectionSurface;    // canonical card surface (= cs.surface in dark, white in light)

  const AppSemanticColors({...});

  @override AppSemanticColors copyWith(...) => ...;
  @override AppSemanticColors lerp(...) => ...;
}

extension SemanticColorsX on BuildContext {
  AppSemanticColors get sem => Theme.of(this).extension<AppSemanticColors>()!;
}
```

Register in both `lightTheme` and `darkTheme` builders.

This avoids polluting `ColorScheme` (Material expects specific semantics there) while giving us a clean `context.sem.xpGold` accessor.

## Risks and Mitigation

| Risk | Mitigation |
|---|---|
| **Migration breaks dark mode** (regressions in 21 files) | Migrate one screen at a time; visual diff before merge. `cs.surface` in dark mode is already wired to `AppColors.inkSurface` (line 40 of app_theme.dart) so dark mode is unchanged by definition. |
| **`@Deprecated` AppColors aliases referenced elsewhere** (`cardDark`, `cardLight`, `surface`, `surfaceVariant`) | Grep for these; if zero refs, delete the deprecated block. If refs exist, migrate them in the same pass. |
| **Modal bottom sheets still render dark on light** because the theme's `bottomSheetTheme` isn't set | Add `bottomSheetTheme: BottomSheetThemeData(backgroundColor: cs.surface)` to both `lightTheme` and `darkTheme` builders. |
| **Status bar icons unreadable** when toggling theme at runtime | Already handled in `app.dart:124–135` via `AnnotatedRegion<SystemUiOverlayStyle>`. Confirm it triggers on theme change. |
| **Profile redesign over-scopes** | Phase A + B2 alone fix the user's "light mode is not good" complaint. B3–B8 are progressive enhancements — ship A first, then iterate. |
| **Existing badges greyscale `ColorFilter`** assumes dark background | Test in light mode; the matrix produces gray that may look muddy on white. May need `Opacity(0.45)` instead of greyscale on light. |
| **Streak calendar logic bug** at `profile_screen.dart:369–376` (window comparison can be off-by-one) | Out of scope for this plan — flag for separate fix. Note in danger zone of plan. |
